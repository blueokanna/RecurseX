# DNS 隐私与失败边界

RecurseX 将上游披露数量作为一次解析的资源约束。它与超时、子查询次数、字节预算一起在发送边界检查，不能被竞速线程、重试、回退或嵌套 DNSSEC 查询重置。

这是一条可验证的工程约束，不是已经证明原创性的密码协议，也不代表解析器无法看到查询内容。

## 配置

在已有、证书校验可用的加密转发配置中设置：

```json
{
  "dns": {
    "privacy": "strict",
    "max-upstream-exposures": 1
  }
}
```

这段配置用于合并到现有配置。完整部署仍须提供默认 `nameservers` 或 `engine.forwarders`、TLS 身份，以及 `forwarderCaFile` 信任根。严格模式不接受 UDP/TCP 明文上游，也不接受缺失默认上游的递归配置。直接使用 Rust 配置的调用者受到发送前检查约束。

| 行为 | `standard`，默认 | `strict` |
| --- | --- | --- |
| 默认允许接触的不同上游 IP 数 | 32 | 1 |
| 同组竞速 | 最多两个工作线程；首个上游为 loopback 时顺序执行 | 顺序执行 |
| 上游传输 | 允许明文；加密传输按现有配置校验 | 必须加密并校验证书 |
| 客户端 EDNS 标识 | 保持现有行为 | 去掉 ECS、Cookie、标签和其他客户端选项 |
| 查询填充 | 不自动添加 | DNS 报文长度补齐到 128 字节倍数 |
| 无匹配转发路径 | 可以迭代解析 | 报错 |
| 披露额度耗尽 | 返回 `Policy` 错误 | 返回 `Policy` 错误 |

`max-upstream-exposures` 只能取 1–32。严格模式设为 2 时允许故障后接触第二个 IP，仍不做竞速。额度为 1 时，第一个目的地不可用会降低解析可用性；这是隐私约束的代价。

## 披露额度的定义

令一次解析已获准接触的上游 IP 集合为 `D`，配置额度为 `B`。发送前在共享锁内执行：

1. 若目的 IP 已在 `D` 中，允许同一目的地上的重试。
2. 否则仅在 `|D| < B` 时将其加入 `D`。
3. 超过额度立即拒绝，不打开该目的地的连接。

失败的尝试也占额度。连接或查询超时不能证明对方没有收到报文，因此不能退款。网络工作预算另行限制重复尝试，避免“同一个 IP 不消耗新披露额度”变成无限重试。

额度按 IP 计算，不按运营商计算。同一运营商的多个 IP 会分别计数；共享一个 IP 的不同服务不能据此认定为同一个隐私主体。该额度是单次解析的约束，不是一天内的域名画像限制。后台刷新使用各自的解析额度，并额外受全局后台预算约束。

本地 hosts、Fake-IP 和缓存命中不需要发送新查询。多线程工作共享任务状态；主调用返回后，已经发出的同步 I/O 仍计费。取消标志阻止失败线程继续尝试后续服务器，无法撤销已经发送的报文。原始截止时间阻止后续发送和接收过期结果，但 HTTP 依赖内部的分阶段阻塞 I/O 不能被该截止时间强制中断。

## 路由与回退

`nameserver-policy` 是显式披露边界，优先于 `fallback-filter.domain`。命中的域名只交给该组；组无效或失败时返回错误，不转给默认组或公共回退组。私有域名的合法 loopback、私网回答也不会被公共地址过滤规则改派。

没有显式策略时，强制回退域名直接进入回退组。其他域名先用默认组；传输失败、SERVFAIL、REFUSED 或地址过滤命中可以触发配置的回退组。默认组为回退预留时间，整个过程继续共享解析截止时间、工作预算和披露额度。配置错误、资源额度拒绝和隐私拒绝不会触发降级。

国内、国外域名的选择依赖本地规则；当前实现没有内置国家数据库。将一个域名同时发送给国内外上游会增加可观察者，不能同时声称它减少了该域名的披露。地址过滤也不是密码学真实性证明；合法地址仍可能属于错误目标。

## Fake-IP 的所有权

池满时只清理超过空闲期限的映射。全部映射仍有效时，解析返回 TTL 为 0 的 SERVFAIL，不重新绑定有效地址，也不回退获取真实地址。AAAA 的排除规则在 IPv6 合成判断之前执行；未分配的池内地址 PTR 查询在本地返回 NXDOMAIN。合成答案的 TTL 不超过映射空闲期限。

空闲期限不等于连接生命周期。代理必须通过映射查询保持活跃映射，并为已建立的连接保存目标。重启时需要恢复映射或隔离旧地址，否则客户端保留的地址仍可能失效。Fake-IP 只覆盖相应 DNS 地址回答，不会自动接管代理之外的流量、应用自带 DNS 或 HTTPS/SVCB 地址提示。

## 隐私边界

DoH、DoT 和 DoQ 保护客户端到上游之间的传输。被选中的解析器仍能看到域名，以及连接的来源地址；DNS 通常不包含 HTTPS 搜索框中的关键词。填充减少报文长度信息，不能隐藏查询时间、连接关系或上游已解密的内容。参见 [RFC 9076](https://www.rfc-editor.org/rfc/rfc9076) 和 [RFC 9250](https://www.rfc-editor.org/rfc/rfc9250)。

[ODoH，RFC 9230](https://www.rfc-editor.org/rfc/rfc9230) 通过代理和目标解析器分离来源地址与查询内容，依赖两者不串通等假设；目标解析器仍能读取域名。本项目尚未实现 ODoH。不能将 DNS 竞速、服务器轮换或填充描述成 ODoH，也不能据此保证服务商不会进行风控。

## 验证入口

`tests/forward_privacy.rs` 使用真实 loopback UDP 上游验证回退可达性、跨组披露额度和显式路由隔离。`tests/tls_identity.rs` 在证书校验成功的 TLS 服务端检查实际收到的查询，验证 EDNS 标识移除和填充。单元测试还覆盖线程预算共享、取消、扩展 RCODE、响应匹配和 Fake-IP 满池行为。

`tests/outbound_factory.rs` 在独立进程安装拒绝连接的 Courierust 出口工厂，验证六种传输均调用该工厂，拒绝后不会回退到系统直连。`tests/http_dns.rs` 验证 HTTP/2、HTTP/3 连接复用及网络切换后的重建。DoQ 单元测试覆盖零 ID、超时接口、身份隔离、乱序分片、FIN 一致性和恶意 ACK 区间。

DoQ 握手必须确认服务端选择的 `doq` ALPN，拒绝缺失、重复或长度不一致的扩展。随机源失败直接返回错误，不生成替代密钥；连接 ID 绑定也必须与握手实际使用的值一致。这些要求来自协议校验，不作为原创设计宣传，参见 [RFC 9001](https://www.rfc-editor.org/rfc/rfc9001.html)。

这些检查证明对应回归用例下的行为。它们不构成独立安全审计、公网互操作、长期压测或首包延迟收益的证明。TLS、HTTP/3 运行时和密码学原语来自 Courierust；DoQ 的 QUIC/TLS 状态机在本项目内实现，不能用 DNS 层测试代替对这些组件的审计。DoQ 尚无完整拥塞控制器、密钥更新或迁移支持，应按实验性传输评估。

当前依赖为 crates.io 发布的 `courierust 1.1.2`。`Cargo.lock` 保存注册表来源与校验和，CI 不再依赖相邻目录或跟随 `main` 的检出。验证时使用 `--locked`；`cargo package --locked --allow-dirty` 会从打包产物重新构建，但不会发布到注册表。这里的本地结果不能替代 Linux、稳定工具链及远端 CI 的实际执行结果。
