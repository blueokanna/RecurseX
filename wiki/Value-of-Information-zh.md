# 信息价值 —— 刷新预算花在哪里

刷新路径有两半，而在这个模块出现之前只建了其中一半。

[`PrefetchPolicy`](Refresh-Theory-zh.md) 回答的是*一个条目是否到期*：把保守新鲜度和一个目标
作比较，跌破就放行。那是一个**阈值**，而阈值能说的只有"这个也看一眼"。

维护循环手里的预算是**有限的** —— `RefreshBudget` 按固定速率发令牌 —— 所以真正决定结果的问题
不是*是否*，而是**下一枚令牌花在哪里买得最多**。过去的答案是"`P_LCB` 最低的那个"，而这是个启发式：
拿系统其余部分所依据的风险泛函去衡量，它一次看不见三件事。

| 阈值看不见什么 | 为什么重要 |
|---|---|
| 一次观测能**教**多少 | 一次刷新报告的是*自上次观测以来*的暴露量。确认一件一分钟前刚确认过的事，几乎不携带证据；确认一小时前确认过的事，携带很多。而在调度器运行的那一刻，两者的 `P_LCB` 是一样的。 |
| 这个答案**值**多少 | `V`，省下的延迟。没人等的记录，无论模型多不确定，都不值一枚令牌。 |
| 这条记录的**等级**能造成多大伤害 | `C·κ`。过期的 TXT 是麻烦；过期的委派会改道一整棵子树。 |

## 目标函数

一次观测的价值，是它带来的**期望风险削减**，用的就是 serve-stale 决策所用的同一个泛函：

```text
R = V · (1 − p) · C · κ
VoI = R(什么都不做)  −  E[ R(观测之后) ]
```

两边都在地平线上取值。设 `age` = 自模型上次观测以来的秒数，`Δ_h` 为地平线：

```text
R(什么都不做)   = V · C · κ · (1 − e^(−λ_hi · (age + Δ_h)))
E[R(观测后)]    = p₀ · R(未变化) + (1 − p₀) · R(已变化)
R(未变化)       = V · C · κ · (1 − e^(−λ'_hi · Δ_h))
R(已变化)       = V · C · κ · (1 − e^(−λ''_hi · Δ_h))
p₀             = P(`age` 内未变化) = (β / (β + age))^α
```

`λ_hi` 是 [`hazard`](../src/hazard.rs) 的可信上界；`λ'_hi` 与 `λ''_hi` 是模型对两种结果分别施加
更新**之后**的上界。`age` 就是这次刷新将要报告的暴露量 —— 这正是"对刚看过的东西再看一眼价值恰为
零"的原因，也正是它是一条**性质**而非巧合的原因：它由
`looking_at_something_we_just_looked_at_buys_nothing` 断言。

### 一个算出来的值

按上面的公式取值，模型全新（`α = 1`、`β = 300`、`δ = 0.05`），`V = 50 ms`、`C = 1`、`κ = 1`、
`Δ_h = 60 s`、`age = 120 s`：

| 量 | 值 |
|---|---|
| `λ_hi` | 0.01915 s⁻¹ |
| `R(什么都不做)` | 48.41 ms |
| `p₀` | 0.7143 |
| `R(未变化)` | 27.99 ms |
| `R(已变化)` | 33.33 ms |
| `E[R(观测后)]` | 29.52 ms |
| **VoI** | **18.89 ms** |

这些是**公式求值**，用这些输入就能从代码里复现。它们不是网络实测，这个仓库里也没有任何东西声称
它们是。

## 为什么用"重放更新"来算

观测后的后验，是通过克隆危险模型、调用**真实刷新路径调用的那同一个 `HazardModel::observe`**
得到的。不是重新推导共轭更新，也不是近似可信上界。

这个选择是这个数字能被信任的原因。重新实现动力学的价值函数等于第二个真相来源，而它的失效方式是
静默的：排序看起来完全合理，却在为一次模型根本不会执行的更新定价。重放只花一次克隆和每个候选两次
有界二分 —— 相对于这枚令牌马上要买的那个网络往返，不算什么。

## 两条不能被混同的界线

**预测可以用在这里；不能用在安全上。** `p₀` 是后验**预测**均值。它在这个模块里是对的，因为价值
就是期望 —— 平均而言我们会学到什么。它在 `risk` 里会是错的，那里的量是"我们错了的概率"，而均值
不是保证。同一条界线本来就分离了 `CacheScore`（排序）与 `risk`（决策），在这里成立的道理一样。

**`C = ∞` 变成一个有限的较大数。** `Absolute` 等级（`DNSKEY`、`DS`、`RRSIG`、`NSEC`、`NSEC3`）
返回无穷系数，因为它绝不能和延迟做交易。排序里不可能放一个无穷：`∞ − ∞` 是 `NaN`，而 `NaN` 的
排序是不可预测的。所以排序用 `ABSOLUTE_WEIGHT = 1000`。这**一点也没有**放松那条禁令 —— 禁令住在
`risk::assess` 里，仍然以 `ClassForbidsStale` 拒绝 —— 这个数唯一的作用是把这类条目放到列表最前面。

## 分配，以及它诚实的规模

每次观测恰好花一枚令牌，所以目标是一个纯粹的和，最大化它的分配就是取最大的 `budget` 个值。功夫
花在**算**这些值上；选择本身是一次排序，没有被包装成别的东西。

## 保留额度，以及它的代价

纯粹按价值排序会造成饥饿。某一类既不确定、又值钱、后果又重的条目可以占满每一 tick 的每一枚令牌
—— 而这种饥饿的代价不只是"那些条目晚点刷新"。一个从未被观测的条目，其证据会按设计（`τ`）衰减，
于是它的界变宽，于是它更频繁地跌破新鲜度下限，于是当查询真的到来时它**不能再被 stale 服务**。
饥饿是自我强化的：调度器跳过的那些条目，恰恰是最需要调度器本该保护的那份保证的。

所以在全局填充之前，每一个出现过的**行为类别**先从自己最好的候选里拿到至多
`reservation_per_class` 个席位。保证恰是这些，不多一点：

> 若预算不少于 `类别数 · reservation_per_class`，则每一个拥有那么多候选的类别，至少贡献
> `reservation_per_class` 个。

低于这个预算，就会有类别一个都拿不到 —— 函数不会假装不是这样。

保留额度只会**降低**总价值：它把席位花在了全局排序本来会跳过的候选上。这就是那个取舍，它是刻意的，
而 `reservation_per_class = 0` 可以让宁愿要最大值的人关掉它。两种行为都被
`the_reservation_gives_every_class_a_slot_before_the_global_fill` 钉住了 —— 它把饥饿与补救并排
断言。

## 行为指纹在这里做什么

指纹是**并列打破者**，而并列在一个 tick 的头部是**常态**：同一瞬间写入的条目有相同的模型、相同的
类别、相同的价值。按名字给它们排序，就是按查询流排序 —— 机群里每台解析器都是同一个顺序，对观察者
可预测，而那正是伪造答案最有机会进入模型的时间窗。指纹让这个顺序对我们可复现、对其他任何人不可
猜测。

它同时是保留额度的**队列键**，因为队列必须是条目一个稳定的性质，而类别是。

## 这不是什么

**只是一步前瞻。** 它给下一次观测定价，而不是给一条策略定价。最优**序列**需要在信念状态上做规划，
逐 tick 的调度器没有理由做那个。这个假设在哪里显现：观测之后，条目在同一地平线内其实还会再被观测，
所以 `E[R(观测后)]` 略微高估、价值略微低估。方向是安全的那一侧，而且它是写出来的，不是藏起来的。

**不是实测声明。** 上面每个数字都是推导出来的。这个模块有的是性质测试 —— 对等级、对惩罚、对价值、
对年龄单调；被"不行动的风险"封顶；无物可学时为零 —— 没有任何性能数字。
