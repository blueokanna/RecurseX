# 越过查表

有人向本项目提出了一个方案：用**行为哈希**取代目的地址路由，用**概率叠加态**取代确定性解析，
让**名字本身就是路由**，并用**全息的几何同步**取代缓存。四条与 DNS 的激进决裂，每一条都被
称为「非结合」——不是扩展公理，而是打破公理。

这一页逐条说明：哪些做不到、为什么做不到；以及其中哪一部分是真的，并且已经进了这个 crate。
之所以这么写，是因为一份列出四项发明、却略掉其中两项违反定理的设计文档不叫有野心，叫错误——
而错误的代价很高：真正立不住的那部分，恰恰是读者会去依赖的那部分。

从这次讨论里落地的两个机制是真的、有测试、并且各自有独立文档：
[`src/behavior.rs`](../../src/behavior.rs) 与 [`src/rendezvous.rs`](../../src/rendezvous.rs)。

---

## 一、行为哈希路由

**主张**：离开网卡的封包不指向目的 IP，而指向目的地的**行为哈希**；路由器按哈希空间里的数学
距离转发，不查路由表、也不问 DNS。

**为什么照原样做不到。** 两道各自致命的障碍。

*发送方算不出来。* 行为是目的地的一个属性，要在一段时间里测出来。而发送方还没到达目的地——
那正是路由要干的事。发送方能算的任何哈希，都是对它**已经知道**的东西的哈希：一个名字、一条
策略、一个提示。那就是名字，而名字我们已经有了。

*哈希空间里的距离不是下一跳。* 就算承认哈希，也不存在「朝距离减小的方向转发」这条转发规则：
路由器需要为空间的每个区域准备一个接口，那个映射就是路由表。想从哈希惰性算出来，就得让每台
路由器都知道全局分布——那是加了额外步骤、收敛性质还更差的路由表。几何路由成立的前提是图被
**嵌入**（例如带面的平面图，如贪心面路由），而嵌入来自物理位置。哈希空间按构造就是均匀随机的，
没有嵌入；在随机图上做贪心转发没有任何可达性保证。

**真实存在、并且已经做出来的部分。** 把**行为**用在**局部**决策里，同时把名字排除在外。
`src/behavior.rs` 用解析器本来就在做的测量——变化率的单侧上界、TTL 及其波动、信任等级、
解析成本——导出一个**带密钥的、粗糙的**行为指纹：每个量按「每次翻倍一个桶」量化（所以不会
抖动），再在启动时从 OS 取来的 128 位密钥下做一个标签。

由此得到两条性质，而它们都是在**修缺陷**，不是在**加功能**：

* **机群不再自我同步。** 两个同样该刷新的条目，过去按名字排序。于是整个机群里持有同一批条目的
  每台解析器，都以同样的顺序刷新同样的名字——权威看到的是一个人群冲锋，而不是一片铺开。指纹把
  顺序去相关，但**不改判据**：排序仍然是 `P_LCB(fresh, horizon)` 升序，动的只是并列项。
* **路径外的观察者无法预测我们。** 当顺序是查询流的一个公开函数时，能看见查询的观察者就知道我们
  下一个会去看哪个条目。而一个条目**上次观测**与**下次刷新**之间的这段时间，正是伪造答案最有机会
  成为进入模型那一个的时间——所以知道日程本身就是一种瞄准手段。密钥去掉它；`Debug` 会遮蔽密钥；
  也**没有**任何返回密钥的访问器，因为那种访问器在现实里的唯一归宿就是日志。

**它不是**地址，不能路由封包，不出现在线上，也不打算出现。

## 二、概率式解析

**主张**：不再返回精确地址，而是返回一个概率分布或「能级轨域」。在建立连线之前，封包存在于多个
可能抵达节点的叠加态中；DNS 变成降低网络熵的漏斗，于是不存在一个固定的权威 IP 供 DDoS 瞄准。

**为什么照原样做不到。** 封包是一串字节。在每一跳它都恰好有一个下一跳，而「观测」不是一种坍缩
状态的物理行为——它就是到达。不存在任何机制能让路由器把封包保持在叠加态里；就算有，它最终仍得
从一个接口出去。分布不是网络能承载的东西，它是**端点**能从中取样的东西，而那是另一个主张。

DDoS 那一半不只是缺乏支持，而是反过来了。去掉固定地址并不去掉目标，只是把它挪走：权威服务器
依然存在、依然有地址、依然是唯一能给区签名的东西。返回「概率云」的解析器仍然要向那台服务器发
查询。真正吸收流量型攻击的是**分布**——anycast、大量互不相关的解析器、以及一个不用问任何人就能
作答的缓存。

**真实存在、并且已经做出来的部分。** 「答案不是单一固定目标」这句话背后合法的机制是**带权
会合选择**（weighted rendezvous），在 `src/rendezvous.rs` 里。一个委派的服务器是候选集；那些
实测期望成本落在容差带内的候选，按构造**在测量分辨率上不可区分**；而在它们**之间**，服务器由
密钥与问题的一个纯函数选出：

```text
score_i = −ln(U_i) / w_i ,    U_i 由带密钥哈希给出，均匀分布于 (0, 1]
选择 argmin score_i
```

三条性质，每一条都是证明而不是断言：

| 性质 | 陈述 | 为什么成立 |
|---|---|---|
| 可复现 | 持有同一密钥与候选集的任何解析器，对同一个问题做同样的选择 | 分数是 `(密钥, 问题, 候选)` 的纯函数 |
| 带权 | 候选 `i` 胜出的概率是 `w_i / Σ w_j` | `−ln(U)` 是速率 1 的指数分布，故 `−ln(U)/w` 速率 `w`；独立指数分布的最小值按速率成比例胜出 |
| 最小扰动 | 撤掉一个候选，**只**改变它原本赢下的那些问题 | 其他分数不依赖当前存在哪些候选 |

第三条在测试里是**精确**断言的——撤掉一个候选后改变结果的问题数，与被撤候选原本赢下的问题数
**相等**比较，而不是落在某个容差内。基于取模的构造会彻底失败，所以没有用它。

与「概率云」的区别值得说明白。**发给客户端的答案不变**：所有记录都返回，RRset 是集合
（RFC 2181 §5.1），而且**这个选择发生在我们与权威之间，不在客户端与我们之间**。客户端看到的是那
个区给的答案。分布是**我们自己下一跳**上的，而那是解析器唯一有资格动手的地方。

安全的那一半是密钥。能算出我们为某个名字将联络哪台权威的攻击者，就能把欺骗尝试精确地瞄准那条
路径。密钥在启动时取自 OS 熵，从不离开进程。

**不声称什么。** 这不缓解对权威的流量型攻击。它去掉的是**机群收敛**——整个解析器机群表现得像
一台机器、对着一个有冗余的服务器集合作战，这是一个真实且常见的缺陷，也是 `affinity_lotteries`
在数的东西。多声称一句就是假话。

## 三、名字原生路由

**主张**：DNS 把名字与地址分离，取消这个分离。网络节点没有 IP，名字**就是**路由；路由器依据名字
里的意图加上实时拥塞状态转发，从而把解析层与传输层合并为一。

**先前技术，说清楚。** 这就是信息中心网络（ICN），并且已经存在约二十年。IRTF 在 **RFC 7927**
（2016）发布了研究挑战，在 **RFC 8569**（2019）发布了架构考量；NDN、CCNx、PURSUIT 都是长期项目，
已有接近生产环境的部署。「以基于名字的路由取代 DNS 层」**不是一个新命题**，以它申请专利会在
第一次审查意见里被拿这批文献对照。在这里把它当作**未被主张**的公理突破来呈现，是这个领域事实
层面的错误。

**真实存在、而且已经在本 crate 里的部分。** 这个想法里属于标准轨、且真正可用的那些：

* **缓存是按名字作键的，不是按地址。** `CacheKey` 是 `(name, type, class, ECS 分区)`。同一个名字
  下的 CNAME 链与 NXDOMAIN 住在同一个键空间中的不同结构里。
* **名字可以携带自己的引导参数**，就在 DNS 内部，今天就可以：**SVCB / HTTPS**（RFC 9460）表达
  `ipv4hint`、`ipv6hint`、ALPN、端口覆盖与 `mandatory` 参数——这是「名字里含路由」里客户端不需要
  一个新互联网就能执行的最接近形式。
* **意图在这里已经是一等层**：`policy.rs` 与 `routing.rs` 实现 `nameserver-policy`、
  `fallback-filter`、`hosts` 与 fake-IP，那就是按名字做策略路由。

这一条不主张任何新机制。诚实的贡献是：本解析器实现了它的标准轨版本。

## 四、全息同步

**主张**：放弃缓存与主从复制。把全球名字空间的状态映射进一个高维几何模型；一次变更就是一次曲率
扰动，所有节点在「光速极限内、同时」感知到它。TTL 消失，因为一致性即时且绝对，于是 CAP 在缓存
层面的取舍被消除。

**为什么照原样做不到。** 三处彼此独立的不可行。

*「同时」与「在光速极限内」不能同时成立。* 同时性是依赖参考系的，而以 `c` 传播的扰动到达远处
节点必然在严格更晚的时刻。那段时间间隔就是传播延迟。对**真值会变**的数据而言的传播延迟，恰恰
就是 TTL 在约束的东西。改个名字不会让它消失；一个有界陈旧度的系统就是缓存系统，无论机制叫什么。

*CAP 是定理，不是实现限制。* 给定一次分区，一个请求要么用可能陈旧的数据作答，要么被拒绝。这是
仅有的两个选项，而选择它们就是「AP」与「CP」所指的东西。没有任何表示法能消除这个选择。**FLP**
进一步说明，在异步条件下确定性共识不可能既安全又活。这些是证明；曲率场不能证伪它们。

*去掉缓存，恰好重新制造出该方案声称要解决的问题。* 缓存正是让解析器不用问任何人就能作答的东西。
删掉它，每个查询都会打到权威——那正是流量型攻击想得到的放大的定义。该方案的 DDoS 主张与它的
无缓存主张指向相反的方向。

**真实存在、而且已经在本 crate 里的部分。** 让陈旧度**可证明**而不是被假定——这是这个想法里唯
一有内容的部分：

* **是可信界，不是猜测。** `HazardModel` 给出变化率的单侧 Chernoff 上界，所以「这份数据仍然
  正确的概率是 `p`」是一句背后有推导的话。运维可以设定他接受的概率，系统能回答是否达到。
* **遗忘作为抗伪造的天花板。** 那个用来建模非平稳性的 `τ`，同时把累积证据封顶在 `wτ`，所以任何
  一串伪造的「未变化」观测都无法把变化率压到零。一个声称完美一致性的系统没有这个天花板，也就
  没有察觉自己被投喂的能力。
* **依赖一致的答案。** 一份过期答案的新鲜度只等于其依赖集合里最弱的那一环，而在**瓶颈**处拒绝，
  才是让刷新值得花的东西。

它们用可走的路径达到了同一个目标：无法被消除的陈旧度，被**界定、测量、并报告**，而不是被否认。

## 实际改了什么

| 模块 | 是什么 | 作用在哪 |
|---|---|---|
| `behavior.rs` | 条目的带密钥、粗糙的行为身份 | 刷新顺序的并列打破点，使机群去相关、使观察者无法预测日程 |
| `rendezvous.rs` | 带权最高随机权选择 + 成本容差带 | 一个问题去往哪台权威，使冗余服务器集合被当作一个集合来用 |
| `voi.rs` | 一次额外观测能买到的期望风险削减 | 有限的刷新预算花在哪些条目上，而不是一个只会说「这个也看一眼」的阈值 |

三者都是 `no_std`，都只用 crate 里已有的原语（带密钥标签用 SipHash-2-4，分数用 crate 自己的
`ln`），都由性质测试而非冒烟测试覆盖，都没有新增依赖。

`engine.affinityBandPct`（默认 10）与 `engine.affinityBandMs`（默认 2）调整带宽；**两者都**设为 `0`
会把它压缩到只剩最便宜的那一个，从而关闭抽签。`stats.affinityLotteries` 报告它实际运行了多少次——
多服务器委派上报 0，意味着带宽只放进了一个候选，那是策略读数，不是故障。

`engine.decorrelateRefresh`（默认 `true`）是同一个思路的另一半：对无法持有密钥的部署，关掉它就能
退回名字序，而 `stats.refreshUndecorrelated` 统计有多少轮维护是那样跑的。两个开关存在的理由是一样
的——**让它们对应的统计量有意义**：一个任何配置都动不了的计数器，是包了一层外壳的死代码。
