# 缓存准入与变化率模型

> 版本: **0.2.6**. 缓存构造检查记录身份，内容判等使用完整规范化记录。统计前提见修正后的刷新模型。


缓存是**语义化**的：键是 `(name, type, class, ECS 分区)`，不是原始报文，所以同名下的 CNAME 链和
NXDOMAIN 住在不同结构里。条目分 hot / warm / cold 三层，外加按名的 NXDOMAIN 存储。

## 可观测变化模型

`HazardModel` 使用近似 Gamma 速率模型；输入是两次成功观测的内容差异，不是期间事件计数。
其 Chernoff 界仅在模型内成立，遗忘和证据上限不构成抗伪造证明。默认关闭过期服务。
完整假设与 union bound 推导见 [刷新模型](Refresh-Theory-zh.md)。

内容比较对去掉 TTL 的规范化记录排序后精确判等，忽略 RRSIG 轮换。
`fingerprint()` 仍可用于诊断和调度，但不单独决定内容是否相同。
记录集构造拒绝混合 owner、type、class 或不匹配的覆盖签名。
转发应答只准入当前问题及其别名链可达的数据；目标不存在不能把已有别名缓存成 NXDOMAIN。

`durability_score()` 用于排名，风险门控使用模型界；两者都不能证明实际内容真实。

## CacheScore 准入

每条条目在插入和命中的时候都打分：

```
CacheScore = α·popularity + β·locality + γ·durability + δ·ttl + ε·cost − ζ·memory
```

默认权重 α=0.30、β=0.18、γ=0.20、δ=0.16、ε=0.11、ζ=0.05。每项都归一化到 `[0,1]`：

- `popularity` —— 该域估计器算出的归一化查询速率；
- `locality` —— 上次被服务的近期程度，按窗口衰减；
- `durability` —— 危险模型 60 秒地平线上的后验预测概率；
- `ttl` —— 相对参考的 TTL；
- `cost` —— 相对参考的解析成本（越难解析越值得留）；
- `memory` —— 相对参考的内存占用（做减法）。

**这个分数是价值排序，不是安全闸门。** 没有任何东西因为它的高低而被服务或拒绝。分低的条目先被
淘汰，分高的条目先被预取。而一份 **stale** 答案能不能发出去，只由风险模型决定，别的都不算。

准入阈值：低于 `min_admit_score` 根本不进缓存；`hot_admit_score` 提升到 hot，`warm_admit_score`
提升到 warm。各层容量是硬上限。

## 淘汰

淘汰是精确且廉价的。每层维护一个以 `(量化分数, 键)` 为键的次级索引，所以"取最低分条目"是
`O(log n)` —— 既不全表扫描，也不做采样。最直观的写法（遍历整层取最小值）在缓存满之后就是每次插入
`O(n)`，等于把填满缓存变成 `O(n²)`，同时把攻击者可选择的工作量塞进插入路径。

从 hot 或 warm 淘汰时，受害者是降一级而不是直接丢弃，所以有价值的条目还有一次机会。这个降级
**刻意不做递归**：级联降级会让单次插入的代价失去上限。

低于 `min_admit_score` 的条目根本不缓存，所以缓存留下的就是评分认为值得留的。

## Serve-stale 与预取

过期条目在 `stale_window_secs`（默认一天，按 RFC 8767 的建议）内**有资格**被服务，客户端 TTL 用
短的 `stale_serve_ttl`（默认 30 秒），同时排一个后台刷新。有资格不等于获准：究竟能不能把 stale
发出去，由答案依赖图的**风险界**与这条记录在本次答案中所属的**后果分级**共同决定。一条委派记录
不是一条地址记录，它拿不到同样的 staleness 地平线。见
[刷新理论](Refresh-Theory-zh.md#4-价值与风险是两个问题)。

## NXDOMAIN 存储

NXDOMAIN 按名存（不按 type），因为它对该名下的所有类型都成立。NODATA（NOERROR 空应答）按
`(name, type)` 键存。负 TTL 按 RFC 2308：`min(SOA TTL, SOA MINIMUM)`，上限 `negative_ttl_cap`
（默认 300 秒）。

## ECS

ECS 与非 ECS 应答绝不混用（RFC 7871 §7.2）。查找是从**请求方自己的分区向上走**，一路放宽
scope，最后落到全局分区：

```
P, P-1, …, 1, 全局
```

其中 `P` 是请求方的前缀长度。第一个命中即返回。更宽的答案可以服务更具体的客户端（它本来就是
为请求方网络的超集算出来的）；更窄的不行，所以这个遍历只朝一个方向走。

有三件事让这个遍历是良定义的：

- **地址是被截断的，不只是被贴了标签。** `truncate_to(addr, bits)` 既做掩码，又把八位组数规范
  化为 `ceil(bits / 8)`，所以 `10.0.0.0/24` 与 `10.0.0.0/25` 不会变成两个只差长度的字符串而撞车。
- **分区由应答决定。** 应答声明的 `SCOPE PREFIX-LENGTH`（RFC 7871 §6）与请求方自己的前缀一起
  折进键：`effective = min(declared, prefix)`。服务器声明得比我们问的更宽，也不能把我们的键放宽；
  而声明 `/0` 的服务器——或者对带 ECS 的查询回了不带 ECS 的应答，按 §7.2.2 就应当读作全局——
  会把条目放进全局分区。
- **负应答同样分区。** 作用域内的 NXDOMAIN / NODATA 存在作用域键下。只有全局分区才写共享的负
  存储，所以一句 `/24` 范围内的“不存在”不能替整个互联网回答。

转介的 NS 与 glue 记录**故意**不分区：它们是关于这个区的委派数据，不是关于查询方子网的答案。

**本实现从不发送 ECS。** 它处理的是收到应答里的 scope。自己发 ECS 需要与每个上游达成客户端子网
协议，外加一份独立的隐私分析，两者都不在这里的范围内。
