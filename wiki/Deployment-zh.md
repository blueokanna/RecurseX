# 部署与失败边界

版本：**0.2.6**。

## 监听与生命周期

`Server::new` 默认只允许回环客户端，即使绑定 `0.0.0.0` 或 `::` 也一样。
局域网服务需在 `ServerConfig::allowed_clients` 明确配置 `IpCidr` 网段。
访问检查会规范化 IPv4 映射的 IPv6 地址；UDP 在入队前拒绝未授权客户端，TCP 在分配处理线程前拒绝。
这是程序接口，当前 `Config` JSON 尚无 `allowed_clients` 字段。

UDP 与 TCP 必须绑定同一端口。使用端口零时，把 `bind_udp` 返回的地址传给 `bind_tcp`。
任一绑定失败都应停止并等待已经启动的服务器线程。当前不提供面向客户端的加密 DNS 监听器。

预取、清扫和周期持久化需要显式启动 `spawn_maintenance()`。
退出时先通知 server 和 resolver，再等待 server 与 maintenance 的句柄结束。
套接字和队列以 100 毫秒间隔检查停止标记；正在进行的解析可能用完剩余上游预算。
停止不等于能够立即抢占依赖内部的阻塞 I/O。

## 资源上限

默认 2 个 UDP 接收线程、8 个 UDP 处理线程、1024 个排队数据报、1024 个并发 TCP 连接，
TCP 空闲超时 30 秒。UDP 接收缓冲配置实际生效，并限制在 512..65535 字节。
移动端应设置更小的队列与线程上限。TCP 上限为零表示显式不限量，不适合不可信网络。
报文读取有总截止时间，持续滴入字节不能无限延长连接寿命。

按源 IP 限速只能尽力而为，伪造源地址能绕开单桶限制。
EDNS 协商限制响应大小，并不限制响应与请求的放大比。
递归服务仍需防火墙、源地址校验和网络侧限速。允许 `0.0.0.0/0` 或 `::/0` 会显式开放公共递归，
进程内资源上限不能代替对流量型攻击的防护。

## 上游行为

纯递归要求网络能够访问权威服务器的 UDP/TCP 53 端口。网络丢弃、重定向或限制这些流量时，
传输恢复算法不能保证这条路径永远成功。备用转发器必须由配置明确选择；
受隐私策略约束的路由不会悄悄访问未配置的公共 DNS。

权威尝试为备用服务器保留时间。UDP 超时或截断可在原截止时间内重试 TCP，TCP 截断不作为完整答案。
回环转发器有备用时，传输失败后避让五秒；网络代次变化清除避让状态。
有效否定回答不会降低端点可用性。

DoT/DoH/DoH3/DoQ 要求配置证书信任根并验证身份。JSON 使用 `forwarderCaFile`，库调用者使用
`EngineConfig::forwarder_roots` 或 `set_forwarder_roots(roots, true)`。
DoT/DoQ 支持分离连接 IP 与 TLS 名称；当前 Courierust HTTP 接口不能为 DoH/DoH3 分离它们，
因此 `host` 必须是与 `ip` 相同的 IP 字面值，证书也需匹配该 IP 身份。
不支持的组合在配置阶段拒绝，HTTP 重定向不跟随。
DoQ 仍属实验性传输，不宣称已完成公网互操作、拥塞控制和连接迁移验证。

安全随机数使用 OS 播种的 ChaCha20，每产生 1 MiB 输出重新播种。
SplitMix64 用于非安全采样与确定性测试。随机数不能代替上游来源、事务 ID 和问题一致性检查。
局部验签不能置 AD，见 [DNSSEC](DNSSEC-zh.md)。

## 观测与排查

`observation::configure(capacity)` 开启记录，默认关闭，最大容量 512。
快照统计完成的解析器调用，不是包数；嵌套调用可能分别记录。
每条记录最多保留八条、每条 256 字节的答案摘要。争用时丢弃并统计观测，不阻塞解析。
`configure(0)` 关闭并清空历史；记录不落盘，清除历史不清 DNS 缓存。

分别验证 UDP、TCP、冷递归、缓存命中、权威否定回答和已配置的备用路径。
应区分响应码、传输错误、证书失败和工作预算耗尽。成功绑定端口只说明监听器已启动，不说明权威解析可达。
